# ScopeRec-C 当前方案：整体架构与绘图说明

本文可以直接交给架构图绘制工具。请画当前的 **ScopeRec-C：置信预算控制的内容条件后缀适配**，
不要把它与早期低秩补丁版 ScopeRec、GenRecEdit 的 FFN 编辑或未来规划功能混合。

## 1. 一句话定义

系统保留训练好的生成式推荐主干与商品语义 ID，通过用户历史和新品内容计算个性化分布，
只在模型实际生成的指定 SID 前缀之后，用有上限的概率预算混合后缀分布，改善新品可推荐性。

图的中心是 **冻结模型 + 输出前缀作用域 + 内容条件分布 + 置信概率预算**，不是训练大模型。

## 2. 整体布局

建议使用横向 16:9 或 2:1 画布，分成两个横向区域：

| 区域 | 占比 | 主题 |
| --- | --- | --- |
| 上方 | 约 30% | 离线准备：编码、基础模型训练、索引和参数选择 |
| 下方 | 约 70% | 请求时推理：历史输入、模型生成、内容支路、概率混合、推荐输出 |

请求时区域从左到右画“输入 → 双支路计算 → 作用域与预算 → 后缀混合 → Beam Search → 输出”。
冻结 T5 主干走上支路，内容匹配与置信门控走下支路，两者只在混合模块汇合。

主色建议：白底；冻结组件使用灰蓝 `#687582`；ScopeRec-C 核心使用青绿 `#07846d`；
辅助索引与控制配置使用浅灰；只有离线可训练模块使用少量暖红 `#b7475c`。
使用统一字体、简短模块名、直角或小圆角框、充足留白；避免装饰渐变和过多技术数字。

## 3. 离线模块

| 编号 | 图中模块名 | 输入 | 输出 | 状态 |
| --- | --- | --- | --- | --- |
| A1 | 商品元数据 / Item Metadata | 标题、features、categories、描述 | 清洗后的商品文本 | 数据源 |
| A2 | 冻结文本编码器 / Frozen Text Encoder | 商品文本 | 商品内容向量 | 使用预训练模型，不微调 |
| A3 | 固定语义编码 / Fixed Semantic-ID Encoding | 内容向量 | 三位语义 token + 一位消歧 token | PCA、码本和旧 SID 版本固定 |
| A4 | 历史交互 / Historical Interactions | 用户序列、时间信息 | 基础训练请求 | 训练数据 |
| A5 | 基础推荐器训练 / Base Recommender Training | 历史 SID 序列 | 训练后的 T5 检查点 | 只在离线基础训练阶段更新 |
| A6 | 内容向量与 SID 表 / Versioned Item Store | A2、A3 输出 | 商品向量、SID-to-item 映射 | 冻结并带版本校验 |
| A7 | 当前新品前缀索引 / Cold-Item Prefix Index | 当前新品集合、向量、固定 SID | 前缀到新品集合的关联 | 数据索引，不是路由神经网络 |
| A8 | 验证集选择 / Validation-Only Selection | 冻结模型、验证请求、有限参数配置 | 锁定的深度、温度和预算参数 | 不使用最终测试指标 |

必须区分：A5 是“先训练后冻结”；A2 和 A3 在适配新品时不重新训练。
新批次只建立或更新候选内容索引，ScopeRec-C 不需要优化额外权重。

主展示的发布版 Software 实验：Sentence-T5 输出 768 维，白化 PCA 到 128 维，
Faiss 三个 256 码本，再追加固定规则的消歧位。目录上的 PCA 使用发布 benchmark 的
全目录设置，不应标成“严格只看过去”。时间窗口实验另有独立配置，不混到主图数字中。

## 4. 请求时模块

| 编号 | 图中模块名 | 行为与输出 |
| --- | --- | --- |
| B1 | 已观测用户历史 / Observed History | 最多 20 件商品；不接入未来正确目标 |
| B2 | 历史 SID 序列 / History SID Tokens | 从固定 SID 表读取，加入用户 token 和 EOS |
| B3 | 冻结 T5 编码器 / Frozen T5 Encoder | 编码历史；编码器状态可在解码步骤间复用 |
| B4 | 冻结自回归解码器 / Frozen AR Decoder | 输入历史编码和已生成前缀，产生基础 token logits |
| B5 | 历史内容查询 / Last-Item Content Query | 读取历史最后一件商品的向量并归一化，不重新用 LLM 理解历史 |
| B6 | 新品相似度 / Cold-Item Similarities | 计算查询向量与当前新品向量的余弦相似度 |
| B7 | 输出前缀作用域 / Generated-Prefix Scope | 根据实际已生成前缀找到对应新品集合 |
| B8 | 分支内容分布 / Branch Content Distribution | 对该分支新品相似度做温度 softmax，得到个性化新品后缀分布 |
| B9 | 置信预算 / Confidence Budget | 用该分支最高相似度计算 sigmoid 门控，预算不超过 alpha_max |
| B10 | 条件概率混合 / Conditional Suffix Mixture | 将基础分布与内容分布组合，使用对数域稳定计算 |
| B11 | Beam Search | 用混合后的概率继续自然解码，并反馈实际生成的前缀 |
| B12 | 商品解析 / SID-to-Item Lookup | 完整 SID 映射到商品；无效路径显式标记 |
| B13 | 排序推荐列表 / Ranked Recommendations | 返回排名、商品 ID、名称和路径分数 |

发布协议使用无合法目录掩码的全词表 Beam Search，生成四个商品 token 与第五位输出。
第五位通常是 EOS，不能画成“自动保证只生成合法商品”。本地演示会保留并标记无效 SID。
另外的时间窗口协议才使用合法前缀树；可以在图角落以“可选协议适配”注释说明。

## 6. 核心公式

历史查询记为 $q(H)$，商品向量为 $e_i$，余弦相似度为 $s_i$。在指定分支 $b$ 内：

$$
R(i\mid H,b)=\frac{\exp(s_i/T)}{\sum_{j\in I_{cold}(b)}\exp(s_j/T)}.
$$

预算由置信门控决定：

$$
a(H,b)=\alpha_{max}\,\sigma\left(\frac{\max_{i\in I_{cold}(b)}s_i-c}{w}\right).
$$

完整路径上的局部混合：

$$
P_C(y\mid H)=P_0(b\mid H)
\left[(1-a(H,b))P_0(y\mid H,b)+a(H,b)R(y\mid H,b)\right].
$$

图中最多放第三个公式，旁边用短句标注“保留前缀概率，只重新分配后缀质量”。
如果画一个混合细节放大框，要注明 token 级权重是根据当前前缀重新计算的后验比例，
不是每一步都机械地使用同一个 alpha。

## 7. 参数与展示口径

| 工作点 | 深度 d | 最大预算 | 温度 T | 置信阈值 c | 宽度 w |
| --- | ---: | ---: | ---: | ---: | ---: |
| 发布 benchmark 主结果 | 1 | 0.05 | 0.05 | 0.5 | 0.05 |
| 独立时间窗口保留优先 | 1 | 0.10 | 0.025 | 0.7 | 0.05 |
| 独立时间窗口新品优先 | 1 | 0.20 | 0.05 | 0.5 | 0.05 |

结构一致，参数按各自验证集选择。不存在可以跨协议直接比较的“全局最高分配置”。
架构图建议只显示主结果第一行，其他工作点在文档说明，不堆进主图。

## 8. 可强调的工程亮点

- 冻结主干和固定 SID，适配阶段无额外可训练权重。
- 基于实际生成前缀控制输出作用域，不需要提前知道正确目标。
- 置信门控与有上限的概率预算，控制新品进入排序时的扰动。
- 基础分支质量不变，关闭适配可在相同输入与目录下恢复原分数。
- 基础模型、向量、SID 和目录带版本校验，支持可复现对照。

限制必须准确：概率预算不等于无遗忘；内容向量需要内存；前缀提前被剪枝仍无法恢复。
当一批新品激活所有粗粒度分支时，“分支外保护”不代表大范围老商品完全不受影响。
发布 benchmark 的 cold 候选身份来自测试子集，这只是评测设定，不是已上线新品发现服务。
